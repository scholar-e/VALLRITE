## Why better phone scores did not improve words

Compared the retained context/LM pipeline to the calibration-selected fixed-crop
continuation, using the same mixed adapter and fixed probability ranker on all
1,140 development clips. The phone metric below is rank one; the word metric
is the probability-selected sentence, potentially from a different phone path.
This compares whole configurations, not an isolated causal crop effect.

| Error count | Retained pipeline | Fixed-crop continuation |
| --- | ---: | ---: |
| Phone substitutions | 2,110 | 18,724 |
| Phone deletions | 34,486 | 10,544 |
| Phone insertions | 20 | 1,361 |
| Predicted phones / reference phones | 22.70% | 79.40% |
| Word substitutions | 2,539 | 7,284 |
| Word deletions | 9,280 | 4,222 |
| Word insertions | 5 | 616 |
| Ranked WER | 93.29% | 95.64% |
| Word oracle WER@5 | 90.12% | 92.36% |

The fixed-crop candidate set recovers length but often supplies incorrect
phones. The decoder consequently produces longer, frequently incorrect word
sequences. That is consistent with distribution mismatch, but does not prove
adaptation will recover the missing information. Only one ranked fixed-crop
output hits the generation cap, versus zero retained outputs: cap handling
alone cannot explain the broad substitution problem.

Phone error improves on 968 clips: word error improves on 329, ties on 403,
and worsens on 236. Across all clips, word error improves on 346, ties on 478,
and worsens on 316, but aggregate errors rise by 298. Clip win counts are not
corpus WER. Alignment ties use diagonal, then deletion; reference totals are
44,586 phones and 12,675 words. These are repeatedly inspected development
results, not independent test evidence.

The previous 1,500-clip decoder training export contains only 31.67% as many
predicted phones as reference phones, with 12,759 deletions, 1,137 substitutions
and three insertions. Its selected 1,000 training and 100 validation clips come
from only eight source videos; all eight occur in both splits. Clip IDs were
disjoint, but this is weak evidence of generalization to other videos. The
earlier current-error report's qualification about nonrandom source selection
therefore matters materially.

Reproducible paired report:
`checkpoints/paired-fixed-errors-20261029/metrics.json`, generated by
`python -m CompetitiveWordDecoder.paired_error_analysis` with explicit phone,
ranked-word and training-export paths. Source hashes, per-clip error deltas,
aggregate counts and alignment conventions are saved. Ranked source hashes,
adapter identity, clip identity and references are checked before comparison.

## Prepared split

`datasets/decoder-training/source-disjoint-950-20261029/` contains frozen
manifests for 750 training, 100 validation and 100 evaluation clips, each from
a distinct source video. Median lengths are 109, 100 and 118 frames. All are
full 60–250-frame clips with transcript/CMUdict labels and pronunciation
coverage at least .95. No phoneme predictions or outcome metrics were used
to select these rows.

Exclude source videos from the current decoder export, reported development
set, original 4,000-example phone-head subset, long fixed-crop training subset,
and fixed-crop calibration set. Exclude normalized transcript matches to the
current decoder export and development, and deduplicate across new splits.
Use SHA256 ordering with seed 20261029, selecting one clip per source video.
There were 973 eligible videos; the initial proposed 1,300-video allocation
failed before producing split files, so it was reduced to 950 before inference.

All 950 video files exist; CTC lengths and cross-split video/transcript
disjointness were verified. Two new split tests plus 13 related decoder tests
pass. Data files remain gitignored; code, hashes and this methodology are
reviewable. This split is held out from the listed recent training subsets,
**not proven untouched by the pretrained encoder or all historical adapters**.
Do not label it an independent end-to-end test. Official test remains unused.

   The existing exporter needs explicit selected-row and fixed-crop support;

   before adaptation, caching all five generated sentences and fixed ranking.
   Keep evaluation references out of training and checkpoint selection.
3. Compare two continuations initialized from that same adapter: clean-only
   versus clean plus actual rank-one phones. Use the same 750 transcripts,

are isolated in `checkpoints/matched-phones-20261029-rejected-axis`. The valid

## Completed pilot results

Both arms completed exactly 375 updates / one epoch. Clean training runtime was
170.63 seconds; mixed was 204.20 seconds, including trainer validation and
cooling pauses. Both saved resumable optimizer checkpoints at steps 250 and
375. GPU/CPU thermal pauses resumed without relaxing limits. No new dependencies
were installed.

| Adapter | Unranked WER | Ranked WER (errors) | Oracle WER@5 | Reference-phone WER |
| --- | ---: | ---: | ---: | ---: |
| Frozen mixed baseline | 95.80% | 95.11% (1,380) | 92.35% | 8.48% |
| Clean-only continuation | 201.03% | 128.95% (1,871) | 118.33% | 5.31% |
| Mixed continuation | 166.99% | 126.53% (1,836) | 123.91% | 8.82% |

All use the same 100 clips, 1,451 reference words, five fixed phone paths,
model revision, generation settings and ranking rule. Oracle error counts
remain identical before and after ranking. WER above 100% is possible because
insertions contribute to the numerator. Clean-reference scores are diagnostic,
not lipreading results. No checkpoint was selected using these outcomes.

| Ranked word errors | Baseline | Clean | Mixed |
| --- | ---: | ---: | ---: |
| Substitutions | 783 | 1,044 | 1,004 |
| Deletions | 572 | 305 | 342 |
| Insertions | 25 | 522 | 490 |
| Capped generations among all 500 | 1 | 30 | 16 |
| Selected capped outputs among 100 | 0 | 3 | 1 |

The continuations replace some deletions with incorrect extra words. Mixed
training is slightly less harmful than clean-only under this ranker, but still
adds 456 errors relative to baseline. Its candidate oracle also regresses, so
ranking alone cannot restore the baseline. Clean-only improves clean-phone
reconstruction while severely damaging visual-input behavior. This pilot does
not support scaling this continuation recipe or promoting either adapter.

Keep the original adapter and existing pipeline. A next bounded investigation
should measure validation WER during adaptation (rather than selecting by
teacher-forced loss), test smaller updates with explicit retention of the
starting decoder's behavior, and inspect termination/length errors. EOS was
already supervised here; merely adding EOS supervision again would not address
this failure. Use validation for any such choices and reserve a newly frozen
evaluation sample for confirmation. No additional experiment was launched.
