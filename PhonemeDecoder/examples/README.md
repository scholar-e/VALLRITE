# Synthetic contract example

These fixtures describe a five-step CTC input with ambiguous initial `P/B/M`,
followed by `AE` and `T`. They are hand-authored, not exported from a checkpoint.
The lexicon permits `pat`, `bat`, and `mat`.

- [request.json](request.json): full 40-class rows, including explicit zeros and
  blank, valid lengths, provenance placeholders, and a lexicon SHA-256.
- [lexicon.json](lexicon.json): one pronunciation per word, each with prior 1.
- [response.json](response.json): an exhaustive arithmetic oracle, generated by
  enumerating all 216 nonzero frame paths, CTC-collapsing each, and summing by
  collapsed sequence. No beam-search implementation was used.

The answer retains all three word alternatives plus the empty sequence. The
values are natural-log CTC sequence masses with no LM, insertion bonus, or
reranker. The result is not a word posterior: probability mass belonging to
other phone sequences is not redistributed to these words. The diagnostic
retained prefix log mass is zero because the enumeration retains all frame paths,
including those without lexical outputs; it is not the sum of returned words.

The request hash is SHA-256 over the exact bytes of request.json. The lexicon
hash is SHA-256 over the exact bytes of lexicon.json. The synthetic producer
hashes are markers only and must not be passed off as installed model fingerprints.

Structural checks use JSON Schema Draft 2020-12. Also check:

1. Every row sums to 1, and the time/mask arrays match `valid_steps`.
2. Every pronunciation uses only the declared phones; priors sum to 1 per word.
3. Every response word/pronunciation resolves in the referenced lexicon.
4. Candidate order and score identities agree with the request's scoring weights.
5. Enumerating the fixture recovers the stored log masses, including the empty
   sequence and blank-separated repeat behavior.

These checks verify the proposed contracts and illustrative arithmetic only;
they do not establish real decoder performance.
